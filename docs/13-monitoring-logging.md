# Monitoring & Logging

**Product:** Aesthetic Coach
**Related documents:** [System Architecture](03-system-architecture.md) · [Backend Architecture](07-backend-architecture.md) · [AI Coaching Engine](09-ai-coaching-engine.md) · [Production Hardening](14-production-hardening.md)

---

## 1. Observability Principles

Every request is traceable end-to-end via a single `requestId` (generated by `RequestIdMiddleware`, [Backend Architecture § 3](07-backend-architecture.md#3-middleware)), returned to the client in every error response ([API Specification § 4](05-api-specification.md#4-error-response-format)) so a user-reported bug can be matched to server logs precisely, not searched for by timestamp guessing.

## 2. Application Monitoring (APM)

- APM tool (e.g., Sentry Performance, or a hosted APM) instruments: HTTP request duration by route, DB query duration/count per request (N+1 detection), queue job duration and failure rate, and AI provider call latency as a distinct span (isolated from general DB/HTTP time so AI latency regressions are immediately attributable).
- Mobile: crash-free session rate, app start time, and screen render performance tracked via the same or a companion mobile-APM SDK (§ 6).

## 3. Error Tracking

- Sentry (or equivalent) captures all unhandled backend exceptions and all unhandled Flutter errors (`FlutterError.onError` / `PlatformDispatcher.instance.onError`, per [Mobile Architecture § Error Handling](08-mobile-architecture.md#7-error-handling)), tagged with `requestId`, `userId` (pseudonymized where required by privacy policy), `apiVersion`/`appVersion`, and environment.
- Errors are triaged with severity: **critical** (auth failures at scale, payment-adjacent [Future] failures, data-loss risk) pages on-call immediately; **warning** (elevated 5xx rate on a single endpoint) creates a ticket; **info** is dashboard-only.

## 4. Performance Metrics

| Metric | Source | Target (ties to SRS) |
|---|---|---|
| API p95/p99 latency per route | APM | NFR-1 |
| AI first-token latency | AI Coaching Service span | NFR-2 |
| DB slow query count | MySQL slow query log + APM | Zero unindexed scans on hot paths ([Database Design § Indexing Strategy](04-database-design.md#4-indexing-strategy)) |
| Queue depth / job latency | Redis queue metrics | `ai-heavy` and `notifications` queues alert independently ([Backend Architecture § Queues](07-backend-architecture.md#4-queues)) |
| AI token spend per day | `ai_usage_logs` rollup | Budget-vs-actual dashboard (see [AI Coaching Engine § Cost Optimization](09-ai-coaching-engine.md#8-cost-optimization)) |
| Mobile crash-free sessions | Crash reporting SDK | ≥ 99.5% ([PRD § Success Metrics](01-prd.md#8-success-metrics)) |

## 5. Health Checks

- `GET /health` (unauthenticated, excluded from rate limiting/logging noise): checks app-process liveness only.
- `GET /health/deep` (internal-network-only): checks DB connectivity, Redis connectivity, and queue-worker heartbeat freshness — used by the load balancer/orchestrator for readiness, not by external monitoring.
- Scheduler heartbeat: a dedicated scheduled task writes a heartbeat timestamp every run; alerting fires if the heartbeat goes stale (catches a silently-dead scheduler, which a simple process-up check would miss).

## 6. Crash Reporting

Mobile crash reporting (Sentry/Firebase Crashlytics) captures native (Android/iOS) and Dart-level crashes with breadcrumbs (recent navigation, recent API calls with `requestId` attached) so a crash report and its corresponding backend logs can be cross-referenced. Crash-free session rate is tracked per app version to catch regressions introduced by a specific release (ties to [CI/CD Pipeline § Release Management](11-cicd-pipeline.md#5-release-management--versioning)).

## 7. Log Aggregation

- All backend logs are structured JSON (not plain text), shipped to a centralized log platform (e.g., CloudWatch Logs, Loki, or the APM vendor's log product), with `requestId`, `userId`, `route`, and `environment` as indexed fields.
- Log levels: `debug` (local/staging only), `info` (request access log, job completion), `warning` (retried failures, approaching rate limits), `error` (unhandled exceptions, failed jobs after retries exhausted).
- **No PII or secrets in logs** — enforced by a logging-context sanitizer that strips known-sensitive keys (`password`, `token`, `Authorization`) before any log line is emitted; reviewed as part of [Production Hardening § Security Checklist](14-production-hardening.md#1-security-checklist).
- Retention: 30 days hot/searchable, 1 year cold archive for compliance/audit needs.

## 8. Alerting

| Alert | Condition | Channel |
|---|---|---|
| Elevated 5xx rate | > 2% of requests over 5 min on any route | On-call page |
| API latency regression | p95 > 2x NFR-1 target sustained 10 min | On-call page |
| AI provider errors | Claude API error rate > 5% over 5 min | On-call page + status note in [AI Coaching Engine](09-ai-coaching-engine.md) dashboard |
| AI daily spend anomaly | Daily spend > configured threshold or > 2x 7-day average | Team channel, non-paging |
| Queue backlog | `ai-heavy` or `notifications` queue depth exceeds threshold for > 10 min | Team channel; pages if sustained > 30 min |
| Scheduler heartbeat stale | No heartbeat in 2x expected interval | On-call page |
| Certificate expiring | < 14 days to expiry | Team channel |
| Backup failure | Nightly backup job fails or verification checksum mismatches | On-call page (see [Production Hardening § Backup Verification](14-production-hardening.md#7-backup-verification)) |
| Crash-free rate drop | > 0.5 percentage point drop vs. prior release | Team channel |

## 9. Dashboards

Recommended dashboard set (Grafana or APM-vendor-native):

1. **Golden Signals** — latency, traffic, errors, saturation for the API tier.
2. **AI Coaching** — request volume per persona, token spend, first-token latency, guardrail-trigger rate.
3. **Business/Product** — DAU/WAU, DFS distribution, AI interaction rate, streak retention — feeding the metrics in [PRD § Success Metrics](01-prd.md#8-success-metrics).
4. **Mobile Health** — crash-free rate, app start time, adoption of latest version.
5. **Infrastructure** — DB CPU/connections/replica lag, Redis memory/evictions, queue depth per queue.

Dashboards are provisioned as code (JSON/Terraform) alongside the alerting rules in § 8, not hand-clicked, so they survive infrastructure changes.
